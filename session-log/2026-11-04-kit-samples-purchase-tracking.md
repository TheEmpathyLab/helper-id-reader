## What was decided

- The products page shows buyers what the $5 kit contains, in two parts: sample images generated from the real kit code (now) and real-life photos taken by Shelton (#95). The video is deferred.
- Sample images use a made-up person (Jordan Rivera), 555-01xx phone numbers and the insurance number `SAMPLE-000000`. Every image carries a "Sample" tag, and the section says the samples use a made-up person.
- The existing community kit photo (`images/helper-id-community-kit.jpg`) stays off the $5 kit listing. It shows the older printed kit and the "look for the helpers" stickers, not the PDFs.
- The kit template problems found while making the samples are tracked as four separate issues (#96–#99). Shelton fixes the templates; the code changes follow.
- Purchase tracking uses GA4 `begin_checkout` and `purchase` events, and each order stores its source in Supabase (`one_time_orders.source`). The source reaches Stripe as `client_reference_id`.
- Source format: `{utm source_medium_campaign | ref_{host} | direct}--{page or ?via= note}`. It remembers the last external source for 30 days.
- Internal links don't carry UTMs. They restart the GA session and replace the real source. Internal links use `?via=`. The Helper Note CTA was switched to `?via=note-why-im-building-helper-id`. The always-UTM rule still applies to outbound links.
- `stripe.com` is an unwanted referral in GA, so purchases keep the buyer's real source.
- Each sales channel gets its own tracked link (#101).

## What was built or designed

- **Sample previews:** `images/kit-sample-wallet-card.jpg` (both sides), `kit-sample-profile-sheet.jpg` and `kit-sample-share-sheet.jpg` (shown on a phone). They were generated by running the real `/one-time-submit` card and profile logic and `generateSharePdf` from `api/server.js` with sample data, then rendered with `pdftoppm` and composed with PIL. The scripts lived in the session scratchpad and weren't kept. Rebuilding means re-running the server code paths on sample data.
- **"What's in the $5 kit" section** on `products.html` and `index.html`: three captioned images that open full size, a "Get My Kit — $5" button and the sample disclaimer. Commit `af6752f`.
- **`hid-attribution.js`:** included on 13 public pages. It saves UTMs, or the referring site, to localStorage for 30 days and `?via=` to sessionStorage. On a kit button click it adds `client_reference_id` to the Stripe link and fires GA `begin_checkout`.
- **`kit-confirm.html`:** fires GA `purchase` ($5 USD, `transaction_id` = Stripe session ID) only when `session_id=cs_…` is in the URL.
- **`api/server.js`:** the kit webhook stores `session.client_reference_id` as `source`; `/admin/kit-orders` returns it. **`admin.html`:** new Source column in Kit Sales.
- **`supabase/schema.sql`:** migration documented. Shelton ran `alter table one_time_orders add column source text;`.

  - GA unwanted referral `stripe.com` added.
- **Verified live:** a real $5 test purchase through `products.html?utm_source=test&utm_medium=test&utm_campaign=tracking-check`. The redirect carried `session_id`; GA Realtime showed `begin_checkout` and `purchase` with source "test"; the admin Source column read `test_test_tracking-check--products`. Commit `a68ebb5`.
